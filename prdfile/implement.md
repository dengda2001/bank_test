# 房东多房源房间租金视图：实施计划草案

> 当前处于规划阶段。以下顺序会随产品访谈更新；用户批准规划并执行 `task.py start` 前不得实施。

## 1. 产品决策与合同测试

- [x] 根据工作簿确认个人责任使用明确金额，支持等分和不等分；“欠租”按责任未覆盖判断，“本人付款”另行展示。
- [x] 根据工作簿确认默认租约基数：同房同一时段一份共同租约，多位参与人分别承担责任；底层保留独立起止日期扩展，但本期只处理整月责任。
- [x] 确认本期用一个房间完整验收收租链路；底层和房子视角按多房产、多房间设计，房子汇总支持多套房记录。
- [x] 确认单房间 MVP 完整支持多人同住、不等分责任和一人代付多人。
- [x] 确认单房间 MVP 保留支出录入、列表、月度汇总和经营净额，支出不影响租金缴满状态。
- [x] 确认发票上传、查看和删除后置到下一阶段；本期只保留一对多附件扩展边界。
- [x] 确认当前 MVP 不实现初始化流程；房产、房间、参与人和责任数据由用户自行准备。
- [x] 确认欠租和催缴按责任未覆盖金额判断；实际付款来源独立展示，完整代付视为责任已结清。
- [x] 确认付款足额覆盖房间全部未付租金时，自动铺满同房责任并将超出本人责任部分记为代付。
- [x] 确认不足以结清房间的部分代付由人工选择目标责任，未确认前剩余金额保持未分配。
- [x] 确认页面结构为房间列表入口 + 带 `room_id` 的房间详情；当前只有一条房间数据，不做固定单房间页面。
- [x] 确认房间列表每行展示所选月份应收、已收、未收和状态，并与详情页共用汇总事实。
- [x] 确认同一月度工作台支持房子/房间/租客三个视角切换，共享月份、汇总和账务口径。
- [x] 确认月度工作台默认进入房子视角（`view=properties`）。
- [x] 确认房子视角每套房展示总房间、已交满、未交满、应收、已收、未收和收缴率。
- [x] 确认空置房计入总房间，但不计入已交满或未交满。
- [x] 确认房子视角增加当月支出和经营净额，且不影响租金收缴状态。
- [x] 确认经营净额为已收租金加已确认其他收入再减有效支出；排除押金、未分配流水、待确认收入和作废记录。
- [x] 确认经营净额中的已收租金按租金所属月份归集，而不是按流水实际到账月份。
- [x] 确认底层付款分配不写死同房限制；本期页面和验收仍只允许处理当前房间，跨房间操作后置。
- [x] 确认房间视角默认展示空置房并标记为空置；有效租约缺账单时必须标记待处理。
- [x] 确认房产公共支出只进入房子级汇总；房间详情和房间经营净额仅统计明确关联目标房间的支出。
- [x] 确认本期不处理月中成员变更、月中换人或按天折算。
- [x] 确认租客视角按“租客 × 房间 × 月份”的责任逐行展示，不跨房间合并同一租客。
- [x] 确认三个视角统一按 `needs_review -> overdue -> partial -> open -> paid -> vacant` 默认排序；房产按最严重房间状态代表其优先级。
- [x] 把房产、房间、多人同住、代付、不等分责任、部分支付、超付、空缺身份、换房、退租和作废整理为表格化场景合同。
- [x] 更新旧 V1 边界，明确本任务覆盖原先后置的“独立房间”和“同房跨租客拆分”，但跨房间操作继续后置。

## 6. 统一维度查询

- [ ] 实现房子列表聚合、房间列表聚合、租客责任列表和单个房间责任详情查询；详情接口显式使用 `property_id` / `room_id`，不写死唯一房产或房间。
- [ ] 房子查询支持同一用户下多套房产，每套房返回总房间数、已交满房间数、未交满房间数、应收、已收、未收、收缴率、当月支出和经营净额。
- [ ] 总房间包含所选月份内有效的空置房；已交满和未交满只统计当月应收大于零的房间，并验证总房间不必等于二者之和。
- [ ] 房间列表从有效房间主数据出发，左关联租约与月度账务事实；验证空置房仍出现，有有效租约但缺账单的房间显示待处理而非空置。
- [ ] 房子、房间、租客查询复用同一账务事实与索引，确保逐层汇总一致。
- [ ] 固化应收、已覆盖、未收、收缴率、未缴满房间和欠款责任人数的定义。
- [ ] 保证分页/筛选只影响行列表，不改变所选范围的汇总口径。
- [ ] 为三个查询实现统一状态排序键：待处理、已逾期、部分缴纳、未到期未缴、已交满、空置；房产行从所属房间取最严重状态，同级按未收金额及稳定名称排序。
- [ ] 增加排序合同测试，覆盖房产含多个不同状态房间、同状态不同未收金额、同金额稳定排序，以及空置房始终排在已交满之后。

## 9. 高风险文件与回滚点

- 迁移文件：必须先验证已有数据升级，禁止依赖删除重建。
- `cmd/truelayer-demo/obligations.go`：月度事实生成和所有 Dashboard 口径的源头。
- `cmd/truelayer-demo/transaction_allocation.go` 与 `ledger.go`：跨租客分配、锁和余额不变量。
- `cmd/truelayer-demo/cash_receipts.go`：现金路径必须与银行路径保持相同责任模型。
- `cmd/truelayer-demo/dashboard*.go`：筛选、分页和维度聚合不得互相污染。
- 回滚边界：新增表/列保留，关闭新账单生成与新 UI，继续读取原有账单；不得反向删除已产生的新账务事实。
