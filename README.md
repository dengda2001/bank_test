# TrueLayer / Tink bank data demo

This repo contains a minimal Go demo for validating whether an Irish bank connection can return account lists, balances, and transactions through an Open Banking aggregator.

The implemented path is TrueLayer first because its Data API maps directly to the validation target:

- OAuth authorization code flow
- `GET /data/v1/accounts`
- `GET /data/v1/accounts/{account_id}/balance`
- `GET /data/v1/accounts/{account_id}/transactions`

IBAN alone is not enough for this test. The account holder must grant consent through the aggregator and the bank's strong customer authentication flow.

## What you need

From TrueLayer:

- A TrueLayer Console account with Data API access enabled.
- `client_id` and `client_secret`.
- A registered redirect URI, for example `http://localhost:8080/callback`.
- Confirmation that the target Irish bank appears in TrueLayer's supported provider list.
- For live bank data, a production/live application and the account holder available to complete bank login and consent.

Optional:

- Provider selector values from the TrueLayer Console auth-link builder, set as `TL_PROVIDERS` or `TL_PROVIDER_ID`.
- A full Console-generated authorization link, set as `TL_AUTH_URL`. If set, the demo uses that link and only overwrites `state`.
- Date range for transactions with `TL_FROM=YYYY-MM-DD` and `TL_TO=YYYY-MM-DD`.
- Local JSONL log path with `TL_LOG_FILE`. Defaults to `bank-data.jsonl`.

Do not put real client secrets in git, chat, or screenshots.

## Run

Create a local `.env` file:

```sh
TL_ENV=sandbox
TL_CLIENT_ID=your-client-id
TL_CLIENT_SECRET=your-client-secret
TL_REDIRECT_URI=http://localhost:8080/callback

# For an Irish provider, use the provider settings generated by the TrueLayer Console.
# TL_PROVIDERS=...
# TL_PROVIDER_ID=...
# Or paste the full generated auth link:
# TL_AUTH_URL=https://auth.truelayer.com/?...
```

Then run:

```sh
./scripts/run-truelayer-demo.sh
```

Open:

```text
http://localhost:8080
```

Click **Connect bank**. After consent, the callback returns JSON containing each account plus balance and transaction responses.

The same callback result is appended to `TL_LOG_FILE` as one JSON object per line. The log contains bank account, balance, and transaction payloads, so treat it as sensitive local data.

## Tink notes

Tink can be added behind the same local callback pattern, but the required credentials and market/provider availability still need to come from Tink's developer portal:

- Tink application `client_id` and `client_secret`.
- A registered redirect URI.
- Confirmation that the Irish bank is available for account aggregation in your Tink environment.
- The user completing consent through Tink Link.

The demo currently avoids adding a second provider until those details are confirmed, so the first live validation stays small and debuggable.
