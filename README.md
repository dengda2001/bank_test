# RentOps bank income demo

This repo contains a minimal Go demo for validating whether an Irish bank connection can return account lists, balances, and transactions through an Open Banking aggregator, then showing incoming bank transactions in a lightweight tenant-billing workspace.

The implemented path is TrueLayer first because its Data API maps directly to the validation target:

- OAuth authorization code flow
- `GET /data/v1/accounts`
- `GET /data/v1/accounts/{account_id}/balance`
- `GET /data/v1/accounts/{account_id}/transactions`

IBAN alone is not enough for this test. The account holder must grant consent through the aggregator and the bank's strong customer authentication flow.

## What you need

From TrueLayer:

- A TrueLayer Console account with Data API access enabled.
- `client_id` and `client_secret`.
- A registered redirect URI, for example `http://localhost:8080/callback`.
- Confirmation that the target Irish bank appears in TrueLayer's supported provider list.
- For live bank data, a production/live application and the account holder available to complete bank login and consent.

Optional:

- Provider selector values from the TrueLayer Console auth-link builder, set as `TL_PROVIDERS` or `TL_PROVIDER_ID`.
- A full Console-generated authorization link, set as `TL_AUTH_URL`. If set, the demo uses that link and only overwrites `state`.
- Transaction start date with `TL_FROM=YYYY-MM-DD`. The transaction end bound is always the current UTC time.
- Local JSONL log path with `TL_LOG_FILE`. Defaults to `bank-data.jsonl`.
- Local refresh token path with `TL_TOKEN_FILE`. Defaults to `truelayer-token.json`.
- Demo admin username with `APP_ADMIN_USERNAME`. Defaults to `ddrzh`.
- Demo admin password with `APP_ADMIN_PASSWORD`. Defaults to `ddrzh512`.
- Session signing secret with `APP_SESSION_SECRET`. If omitted, the server generates one on startup and sessions expire after restart.

Do not put real client secrets in git, chat, or screenshots.

## Run

Create a local `.env` file:

```sh
TL_ENV=sandbox
TL_CLIENT_ID=your-client-id
TL_CLIENT_SECRET=your-client-secret
TL_REDIRECT_URI=http://localhost:8080/callback

APP_ADMIN_USERNAME=ddrzh
APP_ADMIN_PASSWORD=ddrzh512

# For an Irish provider, use the provider settings generated by the TrueLayer Console.
# TL_PROVIDERS=...
# TL_PROVIDER_ID=...
# Or paste the full generated auth link:
# TL_AUTH_URL=https://auth.truelayer.com/?...
```

Then run:

```sh
./scripts/run-truelayer-demo.sh
```

Open:

```text
http://localhost:8080
```

Sign in with the configured demo admin credentials. The app redirects to `/billing`, where you can bind a bank account or refresh with a saved login.

Click **Bind bank account** to start the TrueLayer authorization flow. After consent, the callback checks the local app session, fetches bank data, appends it to the JSONL log, and redirects back to the billing page.

The default scopes include `offline_access`, so the first successful consent stores a local refresh token in `TL_TOKEN_FILE` with `0600` permissions. After that, use **Manual refresh** on `/billing` or open `/refresh` while signed in to get a fresh access token and query again without completing bank login each time. If you use `TL_AUTH_URL`, make sure that Console-generated link also includes the `offline_access` scope, otherwise TrueLayer will not return a refresh token.

Refresh tokens are reusable, but they are not permanent. TrueLayer connections and user consent commonly expire on a 90-day cycle, and access can also fail if the user revokes consent or the bank requires re-authorization. When that happens, bind the bank account again.

The same callback result is appended to `TL_LOG_FILE` as one JSON object per line. The log contains bank account, balance, and transaction payloads, so treat it as sensitive local data.

The billing page reads the latest JSONL entry and renders incoming transactions only. It treats `transaction_type == "CREDIT"` or positive amounts as income. Payer id and payer name are shown as confirmed, inferred, or unknown because those fields vary by bank and provider metadata.

## Tink notes

Tink can be added behind the same local callback pattern, but the required credentials and market/provider availability still need to come from Tink's developer portal:

- Tink application `client_id` and `client_secret`.
- A registered redirect URI.
- Confirmation that the Irish bank is available for account aggregation in your Tink environment.
- The user completing consent through Tink Link.

The demo currently avoids adding a second provider until those details are confirmed, so the first live validation stays small and debuggable.
