# 房间详情页房东视角改造

## Goal

房间详情页（`/rooms/{id}`）现在是一份数据陈列：它告诉房东"欠 1000"，却不告诉他欠了多久，也不给他任何就地收钱的动作。本次改造把页面重排成"先看清欠款、再就地处理"，同时收敛页面上的重复信息与空态骨架。

数据口径、账务事实和查询逻辑都不变——本轮只动展示层与视图数据的派生。

## Requirements

### 1. 逾期天数

- 房间详情页在有逾期责任时显示"已逾期 N 天"，N 由当月到期日与当天日期推出。
- 计算放在 `loadRoomDetail` 里（`period` 与时间已在手），作为视图字段输出，不新增查询、不改账务口径。
- 未逾期、已缴清、空置、无计划时不显示逾期文案。

### 2. 未付高亮

- KPI 行里"未付"是唯一带警示色的卡片；金额与左侧色条用警示色，卡片底色用警示色的淡底。
- "已收"仅在金额大于 0 时用正向色；0 元不得显示为正向色。
- 「租客责任」表的未付列（表头＋单元格）与未付卡同色系，两处呼应。
- 模板里已在用但 CSS 从未定义的 `metric-primary` / `metric-success` / `metric-warning` 三个修饰类，本次补上定义。

### 3. 一键平账

- 「租客责任」每行在未付大于 0 时提供"一键平账"，复用现有的 `collection-settle-form` partial 与其 POST 目标 `/rent-dashboard/settle`。
- 平账后回到本房间详情页（保留房间、月份与来源上下文），不把房东甩回工作台。
- 未付为 0 的行不渲染平账入口。

### 4. 删除并进编辑抽屉

- 页头与移动端底栏不再有独立的"删除房间"按钮。
- 删除入口只出现在"编辑房间资料"抽屉底部的危险区，按钮旁写清后果（连带删除收租安排与历史责任记录、不可撤销）。
- 新建房间的抽屉（`room-create-drawer`）不出现危险区——房间还不存在，没有可删对象。
- 删除的 POST 目标、`action=delete`、隐藏字段与既有鉴权/所有权校验一律不变，只改它在 DOM 中的位置。

### 5. 房间信息补字段

- 「房间信息」补"每月交租日"，取值与计划一致。
- 「房间信息」接管"计划区间"（生效起止）。

### 6. 砍掉「当前收租安排」块

- 整块移除。其"房间月租"等于「租客责任」各行应付之和，"入住租客与责任"等于责任表的行集合，属重复。
- 移除后，月租／缴租日／计划区间归入「房间信息」，`调整安排` 的职责由页头既有的「入住与租金」按钮承担。
- 不新增"更多"下拉菜单（那属于更大一轮的页头重排，见 Out of Scope）。

### 7. 空板块折叠

- 「关联收款」与「代付分配详情」在没有关联收款时默认收起，仅保留一行摘要；摘要里保留登记收款的入口。
- 有数据时展开并渲染原有内容。
- 折叠是否"空"以关联收款笔数为判据，不再以是否有租客为判据（现在的判据会让"有租客但未收款"渲染出空表头）。
- 折叠头内的按钮必须阻止冒泡，否则点击入口会连带展开面板。

### 8. 本页术语

- 「已覆盖」→「已收」，「责任人」→「租客」，只在本页生效。

## Acceptance Criteria

- [ ] 逾期场景下页面出现"已逾期 N 天"，N 与到期日和当天日期的差值一致；非逾期场景不出现该文案。
- [ ] KPI 行中"未付"卡是唯一带警示色的卡；"已收"为 0 时不显示正向色。
- [ ] 「租客责任」表未付列与未付卡同色系，视觉上连成一处。
- [ ] 未付大于 0 的行有可用的"一键平账"，提交后回到本房间详情页且上下文不丢；未付为 0 的行没有该入口。
- [ ] 页头与移动底栏都没有"删除房间"；编辑抽屉底部有危险区且写明后果；新建抽屉没有危险区。
- [ ] 房间信息里能看到"每月交租日"与"计划区间"。
- [ ] 页面上没有「当前收租安排」块，也没有因此丢失月租／缴租日／计划区间信息。
- [ ] 无关联收款时，「关联收款」与「代付分配详情」收起为一行；有关联收款时正常展开。
- [ ] 桌面（1440px）与窄屏（360/390/430px）渲染可用，无横向滚动。
- [ ] 与本次相关的既有测试通过；改动导致的断言更新逐条说明，且不掩盖既有失败。

## 需要 dd 在评审时拍板的一点

补齐 `metric-*` 三个修饰类的定义会**同时影响** `pages/property-detail.html` 与 `pages/rent-workspace.html` 的 KPI 卡（它们也在用这三个类名）。这是把"用了但没定义"的类名补全的正常结果，但确实超出了本页。若希望本轮零外溢，就改为只作用于房间详情页的局部类名，代价是同一套视觉在两处各写一遍。

## Out of Scope

- **累计未收 / 往月欠款**：需要跨月汇总查询，现有查询都锁在单月 `period` 上。
- **催收历史（催过几次、最近何时）**：`/dunning` 有发件人与候选列表，但没有房间维度的催收记录。
- **房间状态与收租状态拆分**：现在同一个 `StatusLabel` 同时喂给未付卡文案和「房间状态」。要拆得动视图契约与数据模型，不只是模板。
- **金额千分位（`EUR 1,000.00`）**：`formatMoney` 是全站共用的，改它会影响所有页面，需单独评估。
- **页头按钮重排 / "记录收款"主按钮 / "更多"下拉**：属于更大一轮的页头信息架构调整。
- **在手写平账方式**：`collection-settle-form` 的四个处理方式里目前只实现了"匹配现有收款"，其余会明确回错。这是既有状态，本次不改。

## Dependencies

- 无前置任务。`collection-settle-form` 与其两个适配器（`/bills`、工作台）已存在，本次是第三个载体。
