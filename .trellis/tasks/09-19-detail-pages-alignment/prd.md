# 详情页对齐

父任务：`.trellis/tasks/09-19-pc-ui-fidelity-alignment`。依赖子任务 ① 先落地。

## Goal

让四个详情页的区块、指标卡、事实区与侧栏结构对齐原型，并补齐房间、租客、流水三个详情页缺失的功能项。

## Confirmed Facts

原型四个详情页的结构（`buildDetails()`）：

- **房产详情**：返回房产管理；操作「编辑资料」「查看全部房间」；4 指标（本月应收 / 已收租金+收缴率 / 本月支出 / 经营净额）；房间收缴概览表（房间/入住/应收/已收/未收/状态/操作-查看房间）；本月收支构成（已收租金 + 已确认其他收入 − 有效支出）；侧栏「房产资料」+「需要关注」。
- **房间详情**：返回房间管理；操作「编辑房间」「新增房间支出」「提醒未付租客」；4 指标（本月房间应收 / 已覆盖 / 未付 / 房间净额）；租客责任表（责任人/个人责任/已覆盖/未付/付款来源/状态，责任人可跳租客详情）；关联收款表（日期/实际付款人/来源/分配金额/关联责任/操作-查看分配）；房间支出 mini-list；**代付分配详情**（4 格：收款金额/本人责任/同住人责任/未分配 + 说明）；侧栏「房间与租约」（所属房产/房间类型/当前租约/租期/账单日/在住人数）+ 风险提示 + 收租时间线。
- **租客详情**：返回租客管理；操作「编辑资料」「录入现金收款」；4 指标（本月个人责任 / 已覆盖 / 仍需支付 / 近 12 月准时率）；缴费历史表 + 范围下拉（近 12 / 24 个月）；「联系与催收记录」+「发送新提醒」；**代付与被代付**表；侧栏「租客档案」+「付款识别」（银行付款人名称 / 付款参考码 + 复制）+ 风险提示。
- **流水详情**：返回流水匹配；操作「编辑分配」「标记非租金」「确认匹配」；4 指标（入账金额 / 建议置信度 / 已分配 / 未分配余额）；建议匹配（金额桥）+ 风险提示；关联账单与对象 mini-list；处理记录（审计行）；侧栏「原始流水」事实区 +「原始描述」多行 code-block + 风险提示。

当前实现的偏差（代码核查结论）：

- **房间详情 CSS 缺陷**：`room-detail.html:104` 把 `room-facts` 与 `room-mobile-facts` 写在同一个 `<dl>` 上；`room-detail.css:20` 的 `.room-mobile-facts{display:none}` 与 `:25` 的 `.room-facts{display:grid}` 优先级相同（0,1,0），后者按源码顺序胜出，导致移动端专用字段在 PC 上重复渲染。正确写法见 `property-detail.html:83` —— 用外层 wrapper 承载 `display:none`，与 `.property-facts` 分开。
- **房间详情代付分配详情**：`room-detail.html:84-88` 区块存在，容器为 `room-allocation-metrics`；格子是动态的（已覆盖 + 每租客 + 未覆盖），原型固定的「未分配」格无对应实现。
- **租客详情缴费历史范围**：`tenant_detail.go:287` 是两个 month input，默认跨 12 个月（`:16`）；原型是「近 12 个月 / 近 24 个月」预设下拉。
- **租客详情付款识别**：`tenant_detail.go:290` 有付款人名单 + ID + 共享/冲突标记；`reference` 在 `:137` 已取数但未渲染，且无复制按钮。
- **租客详情代付与被代付表**：`tenant_detail.go:290` 仅「责任与代付」两行键值；`PaidByOther` 未进入 `tenantDetailPageData`。
- **流水详情原始描述**：`transaction-detail.html:159` 是普通 `<dd>`；原型是多行 code-block。
- **流水详情事实区**：`transaction-detail.html:148-161` 标题为「付款信息」，且无「交易时间」行。
- **流水详情三操作**：`transaction-detail.html:13-30` 只有返回类链接；「编辑分配」「标记非租金」「确认匹配」的动作实现在列表行内 `billing_page.go:308,338`。
- 房产详情已实现「编辑资料」+「查看全部房间」（`property-detail.html:25,59`）与「需要关注」（`:84-86`）；房间详情三按钮已实现（`room-detail.html:27,28,29`）；租客详情两按钮已实现（`tenant_detail.go:279`）。

**一处未解观察**（需在实现时确认，不要预设为缺陷）：在既有截图 `verified-current-desktop-room-detail.png` 中，租客责任表的「付款来源」列渲染为 `—`，关联收款表有表头但无数据行，而 KPI 显示付款记录 1 笔。模板（`room-detail.html:73`、`:80`）与视图模型（`rent_workspace.go:474`、`:497`、`rent_workspace_page.go:292-293`）从代码上看都已接通，无法仅凭代码判定。实现时需实际渲染该页确认是数据问题还是渲染问题。

## Requirements

- 四个详情页的区块顺序、指标卡数量与强调、事实区字段、侧栏内容对齐原型。
- 修复 `room-detail.html:104` 的 wrapper 结构，使 `room-mobile-facts` 恢复窄屏专用；修复后核对 `room-detail.css:20` 与 `:25` 的优先级不再互相覆盖。
- 房间详情「代付分配详情」补固定语义的「未分配」格；保留现有每租客格。
- 租客详情缴费历史范围改为「近 12 个月 / 近 24 个月」预设下拉，默认近 12 个月（与现状一致）。
- 租客详情付款识别渲染付款参考码，并加复制按钮。
- 租客详情补「代付与被代付」表（责任月份/实际付款人/责任所有者/分配金额/结果）。
- 流水详情「原始描述」改为多行 code-block。
- 流水详情事实区补「交易时间」行；标题与原型对齐。
- 流水详情页头补「编辑分配」「标记非租金」「确认匹配」三个入口，复用 `billing_page.go:308,338` 已有的动作，不新写业务逻辑。
- 详情页返回链接与行内跳转关系（含责任人跳租客详情、查看房间、查看分配）与原型一致。
