# 实施计划：模板外置与桌面/移动前端边界

## 实施顺序

### 1. 建立基线与资源清单

- 盘点 `cmd/truelayer-demo` 中共享外壳、工作台页面、CSS、JS 和现有模板测试的渲染入口。
- 记录每个页面的路由、模板名、view data 类型、静态资源依赖和现有桌面/移动断点。
- 先运行现有 Go 测试，保留外置前后的渲染基线；不把已有用户改动或生成文件带入提交。

### 2. 外置模板并接入嵌入资源

- 创建资源目录和 `go:embed` FS，先迁移共享 workspace shell 与一个核心工作台页面。
- 将现有 `html/template` 的 clone/partial 关系改为从嵌入 FS 解析，保留已有 FuncMap 和模板数据契约。
- 增加同源 `/static/` 资源 handler；确认单个 Go 二进制从任意工作目录运行时仍能加载模板和资源。
- 迁移其余本任务范围内的页面模板，删除对应 Go 文件中的大段 HTML 字符串；业务 handler 只保留数据准备和渲染调用。

### 3. 外置 CSS/JS 并整理共享层

- 按 token、基础样式、workspace 外壳、页面样式和页面脚本拆分资源。
- 把已有移动端规则迁移到明确的页面/移动边界，继续使用项目既有 `640px` 约定，不新增未经评审的断点。
- 页面脚本改为静态资源或最小化的页面初始化；不把核心表单提交改成必须依赖 JavaScript 的流程。
- 更新模板资源引用和测试 helper，确保测试断言的是渲染结果/资源契约，而不是旧 raw string 的内部拼接方式。

### 4. 建立共享 view model 与双展示试点

- 选择一个核心列表页作为试点，优先选择数据字段和移动信息架构都较复杂的 `/rent-dashboard` 或 `/billing`。
- 为试点补齐页面级和行级 typed view model，集中处理金额、日期、状态、文案和操作可见性。
- 保留桌面表格模板，新增移动卡片/折叠模板；两者遍历同一份行级 view model。
- 用 Go 渲染测试覆盖：桌面结构默认存在、移动结构存在但桌面隐藏、窄屏规则激活、关键字段和 action 在两端一致。

### 5. 收敛迁移、回归和交接

- 将同一模式应用到父任务需要的其他工作台页面；页面视觉重构留给 `09-18-monthly-rent-workspace-ui`，本任务只验证边界可用。
- 检查新页面没有把 domain struct 直接传入模板，也没有新增 User-Agent/设备判断分支。
- 运行完整测试和静态检查，检查模板资源是否被 Git 正确识别，确认没有遗留的巨大用户可见字符串。
- 记录目录规则、view model 约束、双 DOM 使用条件和未来 SPA/API 的边界，作为后续任务的实施依据。

## 验收命令

实现阶段至少运行：

```bash
go test ./cmd/truelayer-demo
go test ./...
go vet ./...
git diff --check
```

若项目已有浏览器验收脚本，再用真实浏览器分别检查约 `320–412px` 和 `≥1024px` 视口；重点确认移动端核心列表不依赖横向滚动，桌面表格、导航、筛选和表单行为没有回归。

## Review Gate

- 在启动实现前评审本 PRD、设计和实施计划，确认“SSR + go:embed + 双 DOM”仍是本期选择。
- 试点页面完成后先检查 view model 是否真正共享，再迁移其他页面，避免复制出桌面/移动两套数据管道。
- 若发现某页面无法在现有数据契约下表达移动布局，应记录为页面 UI 子任务或 API 契约任务，不在本任务中临时扩大范围。

## 回滚点

- 模板外置与双展示结构分开提交；模板外置异常时可以先回退资源接入，保留业务 handler。
- 每个页面的移动展示激活规则独立；删除对应窄屏激活即可恢复原桌面/移动表现。
- 不修改数据库、repository、账务规则和公共 URL，因此不需要数据回滚。
