# 流水日期自动匹配与租客建议

## Goal

让明显属于某月租金的收入流水自动匹配，并让房东在列表中看出哪些是系统自动完成的；仍需手动处理的流水给出可信的租客建议，减少逐个搜索。

## Confirmed facts

- 上一任务已把银行 description 中明确的租金月份与入账日期建议分开。`TxnDate` 和 reference 不代表租金月份。
- 用户确定：没有明确租金月份时，入账日期处于月初或月底的流水可自动匹配；中间日期仍待确认并显示建议月份。先按爱尔兰当地入账日 1–5 日建议当月、25 日起建议下月；6–14 日建议当月待确认，15–24 日建议下月待确认。
- 用户确定：自动匹配的租客身份可来自唯一的付款人姓名与租客姓名完全相同，或此前确认过的付款人与租客关系；还须满足目标月份租金金额等条件。
- 现有待处理收入中，以日期建议、唯一同名/已记住付款人、明确非租金排除、目标账单金额相等为条件，静态估算有 25 条可匹配，分别指向 25 张账单。执行前须按实际状态重算，不能把估算当执行结果。
- 当前严格后台匹配只信任 `tenant_payers`，并允许明确月份的部分金额自动分配；需要为日期推断收紧金额要求。
- 现有 60 个租客、48 种银行确认的收入付款人姓名。93 条收入的姓名与租客正式姓名完全一致；另有 45 条收入、11 种付款人姓名与租客姓名有较明显的拼写、缩写或中间名差异，可作为人工建议；40 条相似度弱或无候选。模糊建议不能代替人工确认。

## Requirements

1. Description 明确写出租金月份时，继续优先采用该月份。没有明确月份时，只有在上述月初/月底日期窗口，才允许用日期建议作为自动匹配月份；中间日期仍作为待确认建议。
2. 日期推断的自动匹配仅针对收入、非押金/退款/报销等明显非租金收入、唯一可信租客身份、未收的目标租金责任、相同币种以及流水金额恰好等于该责任未收金额。任何条件不满足则留待确认或维持未匹配，不自动分配。
3. 唯一可信租客身份可以来自此前记住的付款人关系，或银行提供的付款人姓名与租客正式姓名完整一致。若两种来源指向不同租客或有多个同名租客，必须待确认。
4. 重新对账时可以处理现有未分配、未暂缓的待处理流水；已有确认分配不改写。新同步流水使用同一规则。整个过程保持幂等。
5. 自动匹配成功的流水在列表和详情/核对界面有清楚的“自动匹配”标记，手动匹配可以区分；标记要能从既有匹配来源稳定推导。
6. 手动匹配抽屉在付款人姓名线索可信时，优先展示建议租客，并继续提供完整租客搜索。模糊建议只能辅助人工选择，不能直接触发自动分配；无明显相似候选时不显示建议。

## Acceptance criteria

- [ ] 月初、月底窗口及 5/6、14/15、24/25 日边界和跨年月份均被验证。
- [ ] 完整姓名唯一匹配或既有付款人关系，在未收额精确相等时可自动匹配；金额、币种、租客身份或账单有歧义时留待确认。
- [ ] 明确 description 月份优先；`TxnDate`、reference、押金/退款/报销不得触发日期自动匹配。
- [ ] 重新对账只处理未分配且未暂缓的流水；重复执行不产生重复分配，已确认历史分配保持不变。
- [ ] 列表及详情能区分自动与手动匹配。
- [ ] 手动抽屉的建议租客与完整搜索互不妨碍；模糊线索不导致自动匹配。

## Decision

- Description 明确写出并能识别租金月份时，保留现有任意入账日可自动匹配的规则；1–5 日和 25 日起的窗口只用于没有明确月份的日期推断。明确月份优先于日期推断。
- 姓名模糊结果只在人工抽屉展示候选，不预选、不提交分配；租客选择仍由人确认。

## Out of scope

- 批量改写已有确认分配。
- 使用 bank reference 或 `TxnDate` 推断租金月份。
