# Design

Use the existing review drawer partial and batch-confirm route on all three transaction surfaces. Let its read model show fully allocated sources for correction but keep add/confirm disabled at zero remainder. Link list/detail rent actions into that drawer; maintain one separate whole-source revoke preview entry and one separate non-rent categorization entry. Persist drafts in existing source-keyed session storage and refresh server-rendered data after mutation.

The detail page starts with one full-width “流水分配” panel. It shows source total and a three-part progress bar for confirmed, current draft (zero until the drawer opens), and remaining, using the drawer's labels and colors. Beneath it, “租客与入账分配” shows effective shares as tenant, month, use, amount, status; voided records remain in processing history. Put “处理分配” in this panel's header to keep it visible on mobile. Remove the right-side quick-match card and use the freed space for source facts and processing history below. No “责任” label appears in this combined panel.

Use the shared red in-app confirmation component for exact-share revoke, populated from server-rendered evidence fields, with a POST to the new allocation route. The same component confirms deferral. Keep GET navigation/standard forms as fallback where practical. Name-search controls use ordinary GET URLs with `payer` set and page reset, allowing the server to fill the top field. CSS exposes that keyword field on mobile. Use green accent for the smart badge and neutral tokens for contextual hints.

`manualTenantSuggestions` stays display-only. Run its current close full-name ranking first. If there are no candidates and the payer name is confirmed, tokenize it, ignore short/common words, and search normalized tenant names and aliases by exact token, then prefix/substring. Deduplicate and show all results in deterministic order, one existing-style button per tenant. Each button says only the tenant name; surrounding text may state the matched payer-name word. Do not promote a word match to confirmed identity. Keep the smart marker only while the active selection came from the still-selected suggestion; ordinary tenant switching clears it across both client and server re-render.

`setSuggestionURLs` currently forces `match_month=group.Period` for roommate links. The review service treats it as an explicit user lookup and sets `Viewed`, yielding the misleading “正在查看” badge. Preserve this month context so monthly facts still load, but carry a separate roommate-navigation origin. Only the explicit month lookup sets `Viewed`. Strip a prior explicit lookup origin when switching tenants; keep draft items in session storage.

`transactionReviewRoommateGroup` should include a room detail URL built from its owner-scoped `RoomID` and `Period`. Render “查看房间” by the room/month summary as a normal link to `/rooms/{id}?period={month}`. The room page revalidates ownership. Keep the tenant buttons in the group as separate review-navigation controls.
