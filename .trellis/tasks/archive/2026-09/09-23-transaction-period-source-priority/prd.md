# 流水租金月份来源优先级

## Goal

让流水的租金月份提示优先依据银行 description；description 未写明月份时，仍给核对人员一个基于转账时间的待确认建议，同时避免把猜测月份用于自动入账。

## Confirmed Facts

- 当前导入逻辑把 description 和 reference 拼接后解析月份，无法区分两者的优先级；解析不到月份时保存为空。
- 严格自动匹配要求有明确解析的月份。转账月份只作为待确认建议，不能让原本待确认的流水自动匹配。
- 流水列表和匹配抽屉都展示解析月份；历史流水也可能仍使用旧解析结果。
- Rosewood 示例付款共 186 条，reference 均有 `YYYY-MM`，但 description 也均有该月份；测试里的银行 reference 还可能是 `IE26090266821225` 一类流水号。当前本地 MySQL 无法连接，尚不能统计真实银行流水中的 reference 月份。

## Requirements

- description 中有可识别租金月份时，以 description 为准，即使与转账月份不同。
- description 中没有可识别月份时，以转账时间所在月份生成待确认建议，并在界面明确标注来源与待确认状态。
- 转账月份建议不得用于自动匹配、自动分配或被当作已经确认的租金月份。
- 保持已有银行流水与已匹配结果正确；历史数据的显示规则与新数据一致。
- reference 只保留为银行原文供核对，不参与租金月份推断。示例数据里的 reference 月份均已出现在 description 中；银行流水号的数字可能被误认为月份。

## Acceptance Criteria

- [x] description 有月份时，显示该月份；与转账月份冲突时仍以 description 为准。
- [x] description 无月份且转账时间有效时，列表和匹配抽屉显示转账月份及“待确认建议”来源。
- [x] 仅有转账月份建议的流水继续待确认，不自动匹配或产生付款分配。
- [x] 已有流水的提示能按新规则展示，已确认匹配关系不被重写。
- [x] 缺失或无效转账时间时不凭空生成月份。

## Scope

- 不根据 reference 自动识别租金月份；不重写已确认的付款分配。
