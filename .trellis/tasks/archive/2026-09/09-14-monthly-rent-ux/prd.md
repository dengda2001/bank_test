# 中文月度收租总览与汇款人自动关联

## Goal

用户打开应用即可理解所选月份应收、已收、未收及需要处理的租客；减少筛选负担与重复关联操作。

## Confirmed scope

- 用户同意创建任务并进入方案对齐；尚未批准实施。
- 四项整体改进：清晰的月度总览、统一圆润控件与友好日期选择、界面中文化、同名汇款人一次关联后联动历史及未来流水。
- 已提出以租金所属月份统计已收，银行实际入账按到账月份另列；待最终方案确认。

## Repository evidence

- 当前登录默认进入流水页 `/billing`，总览位于 `/rent-dashboard`。
- 总览已有按月应收、已收、差额统计；当前界面使用英文和原生月份控件。
- 手动确认只分配当前流水，并在条件满足时补写租客付款人 ID；未保存可信的汇款人姓名关联规则。
- 姓名匹配目前只生成候选；付款人 ID 匹配可自动入账。
- 月份选择先读取备注月份，再使用到账月份；目标月份没有未结账单时会回退至最近的其他未结月份。

## Requirements

1. 登录默认进入本月总览，突出应收、已收、未收、金额收款进度与已缴清户数。
2. 优先展示逾期、部分缴纳、其他未缴租客；可查看全部及展开付款明细。
3. 待确认流水有独立入口和准确数量；未确认收入不计入已收租金。
4. 提供上月、下月、回到本月及月份面板；日期与下拉选择统一圆角、尺寸和交互，适配手机及键盘操作。
5. 应用自有页面的导航、标签、状态、提示及空态使用中文；保留银行原文、人名和币种，不要求翻译外部银行授权页。
6. 关联时默认同时处理同一汇款人的其他未关联收入并记住未来入账；允许仅处理当前一笔，展示影响笔数及完成结果。
7. 自动关联只使用明确、无冲突的关系，不覆盖已有确认；异常集中待确认。
8. 明确租金所属月份与银行到账月份的差异；支出和银行入账置于次级信息区域。

## Acceptance Criteria

- [ ] 登录首屏无需筛选即可看到本月应收、已收、未收与完成进度；无账单显示友好空态。
- [ ] 切换月份后金额、租客列表及相关筛选口径一致；进度在应收为零时正常显示。
- [ ] 补缴上月租金不增加本月已收；本月银行入账可包含该笔且有明确说明。
- [ ] 未缴租客优先展示，已缴清户数的分母来自该月账单而非全部历史租客。
- [ ] 所有自有页面常用操作均为中文，日期/月份/选择面板风格一致且可用键盘关闭与操作。
- [ ] 无付款人 ID 的同名汇款人确认后，其他符合规则的历史与未来流水可自动归属，无须逐笔确认。
- [ ] 多笔分次付款顺序累计正确；重复提交、刷新不重复计算；不同用户数据互不影响。
- [ ] 同名冲突、金额超额、币种不符及月份无法确定时保留待确认，不悄悄分配其他月份。

## Out of scope

- 新银行供应商、汇率换算、催租消息发送、租约重构和自动拆分跨月付款。
- 改写既有已确认收款或批量修正历史所属月份。

## Confirmed product decision

- 用户确认：月份不明确时由用户选择。已知租客的流水没有备注月份且到账月份已缴清时，保留租客归属，显示“待选择租金月份”，不自动填入最近或最早欠款月份。
- 选择界面展示各月份应收、已收和未收；确认前展示目标月份和本次金额。选择月份前不计入任何月份已收；提交后仍校验余额与币种，重复提交不重复入账。

## Planning review

- 产品分歧已解决；最终整体方案待用户审阅后进入实施。
