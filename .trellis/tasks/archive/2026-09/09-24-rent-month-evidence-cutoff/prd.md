# 流水租金月份识别与日期建议

## Goal

让银行流水的租金月份判断符合实际核对习惯：description 明确写出租金月份时采用该月份；否则根据入账日期提出待确认建议，便于逐笔核对。

## Confirmed evidence

- 本地库共有 333 条银行流水，其中收入 179 条、支出 154 条。179 条收入中，去除 `TxnDate` 后，38 条同时有租金关键词和月份；另有 3 条只有月份，分别是押金、材料报销、税款退款。
- 98 条收入 description 含 `TxnDate`。它是 AIB 写在描述里的交易日期，不代表租金月份；TrueLayer `timestamp` 是账户入账日期。
- 现有规则把部分 `TxnDate` 错认作明确月份。已有 17 条确认/部分匹配的收入在排除这一误判后没有明确租金月份；这些历史分配不应被批量改写。
- 用户之前确定：日期推测仅为待确认建议，不触发自动匹配；bank reference 不参与租金月份识别。

## Requirements

1. 银行 description 中的 `TxnDate` 和独立的日期信息不算租金月份。只把与 `rent`、`租金`、`房租`、`月租` 共同出现的可识别月份视为明确租金月份；支持现有月份格式。
2. 明确的租金月份优先于入账日期。例如八月底入账、description 写 `Sep Rent`，识别为九月。
3. 没有明确租金月份的收入，以 TrueLayer `timestamp` 的银行所在地日期生成待确认建议：每月 1–14 日建议当月，15 日起建议下个月；跨年跨月正确。没有有效时间则不建议月份。
4. 界线集中配置，默认从 15 日起建议下个月，后续可以调整。日期建议不能写入明确月份字段或触发自动分配；reference 仍不参与。
5. 读取旧流水时按新规则展示；现有已确认分配、金额、租客关系不批量重算。新同步流水使用新识别规则。
6. 明显非租金的收入（如押金、材料报销和退款）即使写有月份，也不把该月份当作明确租金月份。

## Acceptance criteria

- [x] `TxnDate: 25Apr2026` 不再成为四月的明确租金月份；单独 `TxnDate` 流水只显示待确认日期建议。
- [x] `TxnDate: 01Sep2026 ... Sep Rent` 在八月底入账时仍识别九月为明确租金月份。
- [x] `Deposit Sep`、`Materials Expense May and Jun`、`Repayment May tax` 不识别为明确租金月份。
- [x] 14 日与 15 日界线、十二月到次年一月、UTC 与爱尔兰当地日期边界都有测试。
- [x] 可通过单一配置调整界线，并对无效值安全回退到 15 日。
- [x] 日期建议不会让严格自动匹配入账；已有确认分配保持原样。
- [x] 列表和匹配抽屉展示一致，文案能区分明确月份与待确认建议。

## Out of scope

- 批量修改历史匹配、账单或支付分配。
- 让日期建议自动入账。
- 在本次增加用户界面的规则设置页。
