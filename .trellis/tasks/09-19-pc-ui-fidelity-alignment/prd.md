# PC 端原型 UI 还原度对齐

## Goal

让房东运营工作台在 PC 宽度下，于视觉样式、排版布局、表单/筛选/按钮组件和响应式适配四个维度上对齐 `figma/rentops-desktop-suite.html`，并确保原型中体现的业务功能在当前实现里都存在。

用户明确的判定口径：

- **要还原的**：UI 样式、排版布局、输入框 / 筛选框 / 按钮等控件、以及页面的适配程度。
- **不要求逐字一致的**：文案措辞（意思相同或相近即可）、具体数据值（原型数据仅为布局示意）。
- 原型是视觉与交互的契约；**原型里出现过的功能必须确保存在**。

### 当前实现的已知偏差（本次审计确认）

- **全局外壳**：侧边栏只有单层「工作台」分组、汉字单字图标、无底部状态卡；顶栏只有面包屑，无全局搜索与主 CTA。影响所有页面。
- **收租总览**：维度切换按钮位于页头下方、指标卡上方，原型中它在表格卡内与筛选同行；无统计 chips 行；无区块标题；指标卡无首卡强调；「待人工处理流水」为 2 列卡片双按钮，原型是 3 列紧凑清单单「处理」按钮；房产视角表缺「收缴率进度条」与「操作」列；租客视角缺「一键平账」。
- **房间列表**：`rooms.html:61` 的 `<small>自 {{.ActiveFrom}}</small>` 在 `ActiveFrom` 为空时渲染出孤立的「自」字。
- **房间详情**：`room-detail.html:104` 把 `room-facts` 与 `room-mobile-facts` 写在同一个 `<dl>` 上，`room-detail.css:20` 的 `display:none` 被 `:25` 的 `.room-facts{display:grid}` 按源码顺序覆盖，导致移动端专用字段在 PC 上重复渲染。`property-detail.html:83` 用外层 wrapper 的写法是正确的。
- **断点口径**：原型是 `760px / 1100px` 两档；当前实现是 `640px / 980px`。在 640–760px 区间两者排版不一致。

### 结构性隐患（核查中发现）

`/rent-dashboard` 存在两套渲染路径：有 DB 会话时走 `handleRentDashboard` → `rent-workspace.html`；无 DB 时走 `dashboard.go:210` 的降级模板。两套模板内容不同（降级模板有平账按钮、有移动卡片），`/bills` 同理有两套（`dashboard.go:168-174`）。对齐时需要确认以哪一套为准，并避免两套继续分叉。

## Requirements

**A. 视觉与布局对齐（PC 宽度区间）**

- A1 全局外壳对齐原型：侧边栏三组分组标题、`01`–`11` 数字图标、四项计数、底部状态卡与页脚；顶栏搜索框与主操作按钮。
  - 顶栏搜索框按原型的位置与样式实现，但**不得做成无行为的假控件**。本次它承担当前页面的列表检索（提交到该页已有的 `search` 参数）；跨实体的全局检索属于后续任务。若某页没有列表检索能力，则不渲染该搜索框，而不是渲染一个无效输入框。
- A2 收租总览布局归位：维度切换按钮移入表格卡内并与筛选同行；补统计 chips 行；补区块标题与「演示数据 · EUR」标注；首张指标卡加强调样式；「待人工处理流水」改为多列紧凑清单。
- A3 三个视角的表格列按「合并口径」重排：房产视角保留已交满/未交满/支出/经营净额并补收缴率进度条与操作列；房间与租客视角补齐对应列与操作列。
- A4 十个列表页统一为原型的页头 + filterbar + 表格 + 操作列结构。filterbar 渲染该页**真实具备**的筛选控件；已确认按页渲染而非十页一致（`/tenants`、`/bank` 无 filterbar，不强行补齐）。
- A5 四个详情页的区块、指标卡、事实区与侧栏结构对齐原型。

## Out of Scope

- 手机端（≤640px）的视觉与适配调整。
- 逐字对齐原型文案、逐值对齐原型示例数据。
- 改动账务规则、责任分摊算法或已生成账单的历史事实。
- **三项重量级新功能**，经确认拆为后续独立任务，本次不实现：
  - `/transactions` 银行对账单文件导入（原型「导入银行文件」）——仓库当前只有 `导入旧数据`（`billing_page.go:247`）与 `/bank/sync`，无文件导入流程。
  - 租客详情「联系与催收记录」——需要新的持久化实体，`prdfile/prd.md` 未定义该实体。
  - 顶栏跨实体全局检索——需要跨房产/房间/租客/流水的查询能力。
- 原型「重新载入测试数据」——`figma/DESIGN-HANDOFF.md:9` 要求生产 UI 不得保留原型专属装饰；它是原型演示数据载入器，不做成产品功能。

## 任务拆分

本任务为父任务，持有原型契约、跨子任务验收与最终集成复核。五个子任务各自独立实现、检查、归档：

| 子任务 | 范围 | 依赖 |
|---|---|---|
| ① 桌面契约解冻与 1100 断点 | 更新 `responsive-conventions.md` 的冻结表述、新增 1100 中间档、同步受影响测试 | 必须先于 ②③④⑤ 落地 |
| ② 全局外壳 | 侧边栏三组分组/数字图标/计数/底部状态卡/页脚；顶栏搜索与主操作；toast 组件 | 依赖 ① |
| ③ 收租总览对齐 | 布局归位、chips 行、区块标题、指标卡强调、三视角表格列合并、树形展开、租客视角一键平账 | 依赖 ①；**硬依赖 ④ 先完成**（复用其平账表单） |
| ④ 列表页对齐 | 十个列表页的页头/filterbar/表格/操作列；`/bills` 平账表单补全；`/bank` 添加银行账户 | 依赖 ①，复用 ②；**必须先于 ③ 完成** |
| ⑤ 详情页对齐 | 四个详情页的区块/指标卡/事实区/侧栏；房间详情未分配格；租客详情代付表与范围选择器与参考码复制；流水详情 code-block 与三操作入口 | 依赖 ①，复用 ② |

子任务 ②④⑤ 之间无相互依赖，可在 ① 之后并行推进。**③ 是例外**：已确认串行排在 ④ 之后，因为其租客视角的「一键平账」必须复用 ④ 定稿的表单，避免同一 action 出现两个渲染点。
