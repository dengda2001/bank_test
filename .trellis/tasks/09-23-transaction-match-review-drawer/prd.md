# 流水匹配核对抽屉

## Goal

让房东按「核对当前流水 → 查看同名付款人历史 → 核对目标租金月已入账证据 → 确认归属」的顺序处理单笔银行流水。列表中的「匹配流水」打开宽抽屉，避免在狭窄表格单元格里完成复杂判断。

## Confirmed context

- 当前列表的租客选择器只列出存在未付责任的租客；当系统已识别租客但其被识别月份已缴满时，该人会从搜索选项中消失。
- 现有列表的桌面内联 `<details>` 和手机内联表单把选择租客、选择月份放在历史核对之前。
- 银行流水已有付款人、金额、到账时间、description、reference、解析月份与匹配状态；租金责任及其付款分配已有稳定主键。
- 用户已认可先看当前流水、已识别租客、目标月份的已交证据、同名历史流水，再确认的草图；要求抽屉足够宽，内容不挤压变形。

## Requirements

1. 在 `/transactions` 桌面表格和手机卡片中，待处理收入流水的「匹配流水」进入同一个核对抽屉；保持原列表筛选、排序和页码，关闭后回到原位置。
2. 抽屉首先展示当前流水的付款人、金额、到账时间、description、reference、识别租金月与匹配原因。银行原文与系统判断分别标识。
3. 已唯一识别的租客默认带入，不要求再次输入姓名；允许明确地更换租客。更换选择器可搜索该账户下所有租客，不因某月已结清而隐藏租客。未识别或身份冲突时不预选任何租客。
4. 按所选租客展示相关租金月份的应收、已覆盖、未收；被解析出的月份即使已交清也必须出现。已交清月份展示导致结清的有效匹配流水及其日期、金额、付款人、description，并提供进入该流水详情的入口。月份缺账单或币种不符时给出明确原因。
5. 展示当前付款人的其他银行流水，至少包含日期、金额、description、识别月份、实际匹配月份和状态。可查看该付款人的全部历史记录，且不能把同名视为已确认同一租客。
6. 可入账月份由有效责任余额与币种决定；已交清月份不可直接重复匹配。选择月份后展示本次将覆盖的金额与剩余未分配金额，再由用户确认。最终写入仍走现有服务层校验，防止并发状态变化导致超额覆盖。
7. 桌面抽屉提供足够阅读宽度，以信息对照为主；窄屏改为全屏或近全屏的单列布局。长姓名、description 与金额不得挤坏布局，操作与关闭按钮可用键盘访问。
8. 历史与租金数据按当前 `user_id` 隔离；不从付款人名称推断租客身份，不自动改写已有分配。

## Acceptance criteria

- [ ] 已识别租客但解析月份已缴满时，打开抽屉即可看到该租客与已缴满月份，无须重新搜姓名；该月份显示关联的原流水证据，确认按钮不可将本笔再次记入该月。
- [ ] 同一场景中，若另一月份仍有相同币种的未付责任，选中后能看到本次覆盖额和余款，并可通过现有确认流程成功匹配。
- [ ] 未识别身份时，租客搜索包含所有账户内租客；选择一个当前没有可匹配月份的租客也能查看其历史与明确的空状态。
- [ ] 从当前流水能查看同名付款人已关联及未关联的历史流水，并能进入已交月份的原匹配流水详情。
- [ ] 抽屉关闭、提交成功或失败后保留合理的列表上下文；错误可见且不会静默丢失当前流水。
- [ ] 1440px、1024px 与 390px 视口下无文档级横向溢出、关键内容裁切或按钮重叠；抽屉可滚动、可用 Escape 关闭并恢复焦点。
- [ ] 用户隔离、已缴满防重复、币种不符、已撤销分配不计入证据，均有验证。

## Out of scope

- 修改自动匹配规则或重新分配已确认的旧流水；旧流水只提供查看及现有修改入口。
- 在抽屉中处理押金、其他收入或跨房间拆分；这些操作继续进入流水详情。
- 新增数据库表或迁移历史账务数据。
