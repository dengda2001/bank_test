# 流水匹配核对抽屉：技术设计

## Boundaries

- 入口仍是 `/transactions`。`GET /transactions?...&match=<transaction_id>` 在原列表上方渲染核对抽屉，关闭时移除 `match` 及抽屉专用参数；列表筛选、排序、分页保持不变。桌面和手机使用同一服务端数据及同一确认接口。
- 不新增账务写入路径。抽屉的最终提交继续调用 `transactionService.confirmRentMatch`，服务层再次校验用户、交易方向、租客、月份、责任余额和币种。
- 抽屉数据由新只读投影构建：当前流水、唯一识别的租客、所选租客的月责任及有效分配证据、同付款人的历史流水。所有数据库查询带 `user_id`，不得用相似姓名直接推断租客 ID。
- 抽屉采用现有 workspace drawer 视觉基元；页面自身增加宽版样式。桌面宽度建议 `min(960px, calc(100vw - 24px))`，主要证据区在宽屏可双列；≤640px 单列全屏/近全屏滚动，底部确认区保持可见。宽度是实现目标，可在浏览器验收时微调。

## Read model

1. 加载选定流水并确认归属当前用户；使用现有匹配决策计算唯一识别租客。候选租客即使没有未付责任也保留在抽屉，表单不再从 `availableRentManualMatchOptions` 推出租客全集。
2. 更换租客控件使用当前用户的完整租客列表。首次打开时，唯一识别租客为默认值；未识别或冲突时为空。更换租客只改变本次人工核对目标，不会自动修改付款人关系。
3. 查询目标租客的有效 `rent_obligations`，按月份生成应收、已覆盖、未收及可匹配状态。描述解析出的月份固定出现，哪怕已交清或缺少账单；其他月份按时间倒序展示。可选月份必须有正数未收、币种相同。每个月按 `min(流水未分配余额, 责任未收)` 展示本次预计覆盖额与剩余流水余额。
4. 对目标租客月责任批量查询有效房租分配，再批量读取其来源 `payment_transactions`，展示原始日期、付款人、description、分配金额及详情链接；已撤销、非房租分配不作为已交证据。保持历史快照语义。
5. 同付款人历史以稳定付款人 ID（若确实可用）或标准化后相同的银行付款人名称查询，包含已匹配及未匹配流水，排除当前笔，按到账时间倒序分页。历史列表明确标注「同名流水供核对」，不把它当身份确认；每行同时展示银行识别月与有效分配的实际租金月。若暂无同名流水，显示明确空状态。
6. 对所选租客没有有效责任、解析月已结清、币种不同等情况分别说明原因。高级拆分、押金及其他收入继续通过流水详情处理。

## Interaction and URL contract

- 列表中待处理收入行的「匹配流水」改为指向抽屉 URL 的链接，不在表格单元格内展开表单。手机卡片同样使用该链接。`查看详情` 保持原用途。
- 抽屉阅读顺序：当前流水 → 已识别租客/更换 → 相关月份和已入账证据 → 同名历史流水 → 确认区。具体视觉分栏可把月份证据和同名历史并排，但 DOM 阅读顺序保持一致。
- 月份使用可访问的单选卡片；已结清或币种不符的卡片可阅读但不可选。每张卡片自带预计覆盖额/余款，底部确认按钮仅在选中可入账月份时启用。最终提交仍为 `tenant_id + period + transaction_id + remember_payer`。
- 切换租客通过保留列表上下文的 GET 请求重载抽屉；同名历史分页也只改变抽屉专用参数。关闭链接删除专用参数并回到列表。
- 提交成功返回原列表；提交失败重新打开同一流水的抽屉并显示错误，避免用户丢失核对现场。失败回跳 URL 从经过白名单过滤的列表 URL 和服务端已验证的流水 ID 构造，不接受任意外部地址。
- 抽屉遵循现有关闭模式：关闭按钮、背景、Escape；打开时聚焦标题/第一个有效控件，关闭后回到触发链接。无脚本时链接与表单仍可完成关键流程。

## Compatibility and trade-offs

- `/transactions?detail=<id>` 的完整流水详情和现有分配/撤销操作继续保留。列表的内联匹配表单由抽屉替代；首页处理流水暂不改，以免扩大本次改造范围。
- 既有 `transactionReturnTarget` 不接受抽屉参数；确认失败所需回跳由服务端专门构造，不能放宽通用 `return_to` 白名单到任意 `match` 值。
- 同名历史可能包含不同自然人，因此展示原始付款人和匹配状态，但不基于它自动确认身份。浏览器中只渲染一页历史；分页保证所有同名记录可查看且不会把数百条记录塞进抽屉。
- 无 schema 迁移。回滚时移除抽屉入口及只读投影，确认服务与账本事实不变。
