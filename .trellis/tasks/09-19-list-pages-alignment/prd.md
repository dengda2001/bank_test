父任务：`.trellis/tasks/09-19-pc-ui-fidelity-alignment`。

**依赖**：① 先落地。**③ 依赖本子任务先完成** —— ③ 的收租总览租客视角要复用本子任务定稿的平账表单（见下）。

## Goal

把十个列表页统一为原型的页头 + filterbar + 表格 + 操作列结构，并补齐应收账单的平账表单与银行设置的账户操作。

## Requirements

- 十个列表页统一为「页头（标题 + 主操作按钮）+ filterbar + 表格 + 操作列」结构。
- filterbar 渲染该页真实具备的筛选控件；不渲染该页无数据支撑的假控件（已确认决策，见下）。
- 每页补齐原型要求的行内操作；「查看详情」在有详情页的列表上全部渲染。
- `/bills` 平账表单补齐：待平账责任只读区、处理方式下拉、平账金额、生效日期。**不改变已有字段名与 action URL。**
- 该表单需可在**行内**被复用（③ 的收租总览租客视角要渲染同一套），因此标记结构不得依赖 `/bills` 特有的页面上下文。定稿后回报给 ③。
- 处理方式下拉先只启用「匹配现有收款」；其余三项可选，提交时返回明确的未实现提示。
- `/bills`「生成本月账单」由自链接改为显式生成动作，语义与现有幂等行为一致。
- `/dunning` 主操作文案对齐原型「批量发送提醒」。
- `/bank` 补「添加银行账户」；「同步银行流水」文案改为「立即同步」。
- 修复 `rooms.html:61` 的孤立「自」字。
- 列表页的筛选/排序/分页/detail-return 上下文保持不变。

## 已确认的决策

**filterbar 按页渲染其数据支撑的筛选控件，不强制十页齐全**（用户已确认）。

核查实据（各页模板中实际的筛选控件）：

| 页面 | 搜索 | 状态 | 月份 |
|---|---|---|---|
| 房产 / 房间 / 租约 / 费用支出 / 现金补录 | ✓ | ✓ | ✓ |
| 应收账单 `/bills` | ✓ | ✓ | ✓ |
| 流水匹配 `/transactions` | ✓ | ✓（`match_status`） | ✓ |
| 催收任务 `/dunning` | ✓ | ✓ | ✓ |
| 租客管理 `/tenants` | ✗ | ✗ | ✗ |
| 银行设置 `/bank` | ✗ | ✗ | ✗ |

`/tenants`（`main.go:2605-2622`）与 `/bank`（`page_data_routes.go:1511`）**整个 filterbar 都不存在**，不是仅缺月份。`/bank` 是授权与同步设置页，没有月份概念 —— 给它加月份下拉无论怎么实现都是无行为控件，正是父任务 A1 明令禁止的。

因此"十页严格齐全"不可达，非取舍问题。父任务对应验收项已同步改为「每页具备其数据支撑的筛选控件」。

`/tenants` 若日后需要贴近原型，可另起任务补「查该月有账单的租客」的后端查询 —— 那超出 UI 对齐范围，本子任务不做。
