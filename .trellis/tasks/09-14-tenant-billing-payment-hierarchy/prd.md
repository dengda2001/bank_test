# 租客端账单与缴费流水父子展示

## Goal

在租客维度查看最近三个月的收租情况。每个月先展示一条可读的月度汇总（应收金额与实际收款金额），同一个月的多笔转账合并到该汇总下；点击租客、月份和流水明细时逐级展开，既能快速判断欠款，也能追溯每一笔实际流水。

## Repository evidence

- 数据库已有 `rent_obligations`，按 `user_id + tenant_id + period_month` 唯一标识一条租客月度应收账单，并保存应收金额、已收金额、币种和状态。
- 数据库已有 `payment_transactions` 保存银行原始流水；`payment_allocations` 通过 `rent_obligation_id` 和 `payment_transaction_id` 将实际收款分摊到月度账单，并保存本次分摊金额与确认信息。
- 一个 `rent_obligation` 可以关联多条 `payment_allocations`，因此模型已经支持同月多次转账累计为一条账单的实际收款；当前确认逻辑也会累计 `paid_amount_cents`。
- `/rent-dashboard` 当前按选定月份展示每个租客一条月度行，点击后展开该月份的收款明细；不是最近三个月，也不是租客管理页中的租客详情。
- `/tenants` 当前只展示租客资料，没有账单、月度汇总或缴费明细字段/查询。
- 当前后端主要围绕“单月总览”组装数据；没有现成的租客近三个月账单查询或两级父子视图数据结构。
- 当前流水描述解析支持 `9/26`、`2026-09`、`Sep 2026` 和 `September` 等格式，但不支持银行描述中的紧凑英文月份格式 `JULY26`。
- 工作区已有未提交改动，涉及月度总览和流水筛选；本任务规划与后续实现应保留这些用户改动，不覆盖或回滚它们。

## Requirements

1. 在 `/tenants` 租客列表中为每个租客增加可展开的缴费历史入口，默认以当前月份为基准展示当前月与前两个月。
2. 租客展开后按月份展示月度账单父项，每月一条，至少包含月份、应收金额、实际收款金额、未收金额和状态。
3. 一个账单父项下可展开多条实际缴费流水子项；子项展示金额、到账时间、描述/参考号及当前已有的确认来源等可追溯信息。
4. 月度实际收款必须由该月账单关联的已确认分摊汇总得出；同月多笔转账不重复显示为多个顶层账单。
5. 没有缴费的月份仍应显示应收账单和零实际收款，避免用户误以为没有账单。
6. 展开/收起应支持鼠标和键盘，并保持现有租客/账单页面的登录隔离和用户数据隔离。
7. 不改变银行原始流水；已有账单和分摊记录应可继续被当前月度总览使用。
8. 默认保持租客历史收起，避免租客较多时页面初始过长；展开状态由用户操作控制。月度账单父项也默认收起，点击月度汇总后再展示流水子项。
9. 流水描述中的紧凑英文月份格式（例如 `JULY26`、`SEP26`）必须解析为对应的账单月份，并继续兼容已有日期格式。

## Acceptance Criteria

- [ ] 租客列表中的租客可展开查看最近三个月，每个月最多有一条月度汇总父项。
- [ ] 某月存在三笔缴费时，月度父项显示该月应收总额与三笔实际收款之和，展开后可看到三条对应明细。
- [ ] 某月没有已确认缴费时，仍显示该月应收金额、实际收款为 0 和正确的未收状态。
- [ ] 月度汇总和明细金额、币种与 `/rent-dashboard` 的单月口径一致，不把未确认流水计入实际收款。
- [ ] 同一租客可同时展开/收起租客历史和月度明细；刷新页面或重复打开不会重复计算或产生新分摊。
- [ ] 未登录用户不能读取该历史；不同用户不能看到其他用户的租客、账单或流水。
- [ ] `JULY26`、`SEP26` 等无空格英文月份格式能解析为正确的 `YYYY-MM`，无法识别时才回退到流水交易日期。

## Out of scope

- 本轮不重构银行流水导入、付款匹配规则、跨月拆分或汇率换算；仅对现有月份解析器做向后兼容的格式扩展。
- 本轮不新增租客自助登录/对外分享链接；“租客界面”暂按当前登录用户的租客管理/租客列表界面理解。
