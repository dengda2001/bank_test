# 收租总览对齐

父任务：`.trellis/tasks/09-19-pc-ui-fidelity-alignment`。

**依赖**：① 先落地；**④ 必须先于本子任务完成**（见下方「与 ④ 的硬依赖」）。

## Goal

让 `/rent-dashboard` 的区块布局、三视角表格列与展开交互对齐原型，并补上租客视角缺失的「一键平账」入口。

## Confirmed Facts

- 页面模板是 `web/templates/pages/rent-workspace.html`；视图模型在 `rent_workspace.go` 与 `rent_workspace_page.go`。
- **结构性隐患**：`/rent-dashboard` 有两套渲染路径 —— 有 DB 会话走 `handleRentDashboard` → `rent-workspace.html`；无 DB 走 `dashboard.go:210` 的降级模板。父任务 `design.md` §2.3 已决定**以 `rent-workspace.html` 为对齐基准**。
- 当前与原型的具体偏差：
  - 维度切换按钮（房产/房间/租客）位于页头下方、指标卡上方；原型中它在表格卡内与筛选同行。
  - 无统计 chips 行（原型 `dimensionSummary`：`本月共 N 套房产|间房|条租客责任`、`逾期未缴 N`、`部分缴纳 N`、`已缴满 N`）。
  - 无区块标题（原型 `按房产查看 / 按房间查看 / 按租客查看` + 副标题 + 右侧「演示数据 · EUR」）。
  - 4 张指标卡无首卡 `.main` 强调样式。
  - 「待人工处理流水」当前是 2 列卡片、双按钮；原型是 3 列紧凑清单、单「处理」按钮，右上「查看全部流水」。
- 当前表格列（`rent-workspace.html`）：
  - `:49` 房产视角：房产|房间|已交满|未交满|应收|已收|未收|支出|经营净额|状态（缺收缴率、缺操作列）
  - `:108` 房间视角：房间|入住人数|应收|已收|未收|收缴率|到期日|状态（缺操作列）
  - `:130` 租客视角：租客|房间|个人责任|已覆盖|未付|付款来源|状态（缺收缴率、缺一键平账、缺操作列）
- 租客视角「一键平账」只存在于降级模板 `dashboard.go:472,476`，`rent-workspace.html:130-136` 无任何操作按钮 —— 这是首页租客视角缺平账入口的根因。
- 原型操作列口径：租客行且未付 > 0 显示「一键平账」，**所有行**都有「查看详情」。
- 原型排序：`未缴 → 未缴满 → 已缴`，同级按剩余未收降序，再按应收降序。仓库已有统一排序 `needs_review -> overdue -> partial -> open -> paid -> vacant`（`prdfile/prd.md:93`）。
- 现有展开实现用原生 `<details>/<summary>`（`workspace-room-mobile`、`workspace-tree-mobile` 等类），父任务 `design.md` §2.5 已决定**继续用原生元素，不引入 JS 状态管理**。
- 用户已确认房产视角表格采用**合并口径**：保留 PRD 业务列（已交满/未交满/支出/经营净额），**并**补原型的收缴率进度条与操作列。
- 「演示数据 · EUR」是原型的演示标注。父任务未排除它，但 `DESIGN-HANDOFF.md:9` 禁止保留原型专属装饰 —— 处置见下方「已确认的决策」。

## Requirements

- 维度切换按钮移入表格卡内，与房产/状态下拉同行。
- 新增统计 chips 行，4 个 chips 的数据取自当前维度已加载的统计。
- 新增区块标题与副标题，随当前维度变化；右侧标注按已确认决策只渲染币种，不渲染「演示数据」。
- 4 张指标卡的首卡加强调样式。
- 「待人工处理流水」改为 3 列紧凑清单，单「处理」按钮，右上「查看全部流水」链接。
- 房产视角表格补收缴率（百分比 + 进度条）与操作列，同时保留 PRD 业务列。
- 房间视角补操作列。
- 租客视角补收缴率与操作列，并在未付 > 0 时显示「一键平账」。
- 操作列「查看详情」在三个视角的所有行都渲染。
- 树形表格支持逐级展开/收起；点行、Enter、空格均可触发；`aria-expanded` 随状态更新。
- 排序在现有统一口径内实现原型的次级排序（同级按剩余未收降序，再按应收降序）。
- 平账入口沿用子任务 ④ 在 `/bills` 上补齐的表单，不另起一套（见下方「与 ④ 的硬依赖」）。

## 已确认的决策

**区块标题右侧只保留币种，去掉「演示数据」**（用户已确认）。

原型该位置显示 `演示数据 · EUR`，其中「EUR」是币种，「演示数据」是原型演示态标注。处置：由服务端按实际币种渲染（如「EUR」/「欧元」），移除「演示数据」四字。

理由：`figma/DESIGN-HANDOFF.md:9` 要求生产 UI 不得保留原型专属装饰与预览标签，「演示数据」与它们是同类；而币种是真实信息，去掉会丢语义。父任务已写明不要求逐字对齐，只要求意思相近 —— 币种的意思保住，演示标记的意思本就不该保。
