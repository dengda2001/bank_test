# 多租客与跨月流水匹配

## Goal

让房东在同一个「匹配流水」抽屉里核对租客历史月份，将一笔银行收入分配给多位租客或同一租客的多个月份，并在最后一次确认入账。银行原始流水保持不变。

## Confirmed context

- 当前抽屉保留「查看该租客」的月份和已入账证据，以及右栏的同付款人历史流水。
- 当前抽屉一次只能确认一个租客和一个月份；账本服务已经支持一笔流水的多条租金分配及一次原子提交。
- 用户已确认「查看租客月份 → 加入分配草稿 → 查看另一租客／月份 → 最后一次确认」的交互，且要求同一租客一次交两个月。
- 仓库有其他未提交更改；本任务不覆盖或回退它们。

## Requirements

1. 抽屉中的「查看该租客」继续展示该租客每月应收、已收、未收及原匹配流水证据；右栏同付款人历史流水继续可查看与分页。
2. 可入账月份提供「加入分配」。点击后在抽屉内形成未保存草稿，允许编辑金额、移除；切换租客或翻页历史不得清空草稿。
3. 同一笔流水可选择不同租客的月份，也可选择同一租客的不同月份；同一租客与月份的草稿不可重复加入。
4. 抽屉清楚区分已有确认分配、此次草稿分配、原流水金额和剩余未分配金额。部分关联的流水可继续分配余额；已确认分配不因查看、添加或取消草稿而改变。
5. 只在最终「确认分配」时写入全部草稿；服务端基于最新责任及流水余额一次校验并原子保存，禁止超额、跨用户、无效月份、币种不符及重复提交。
6. 付款人关系单独确认；多目标分配时不自动把付款人同时关联到所有责任租客。
7. 当月或未来月份若尚未生成责任，用户能明确选择该月份进行核对与分配；只在明确选择付款月份时生成对应责任事实。
8. 桌面与手机均可使用；错误返回抽屉并清楚提示，成功返回原列表上下文。

## Acceptance criteria

- [x] €1,200 流水可在一个抽屉中加入 A 九月 €600、B 九月 €600，一次确认后生成两条有效分配、两人的责任各覆盖 €600，流水剩余为零。
- [x] 同一租客九月和十月各 €600 可一次加入并确认；切换查看租客和同付款人历史分页时，两条草稿均保留。
- [x] 已部分关联流水显示已有分配，仅允许使用当前余额新增草稿；合计不足时明确显示仍有余款。
- [x] 已交清、币种不符或不存在的责任不能加入；超额及并发余额变化导致整批失败，没有部分写入。
- [x] 提交重试不会重复入账；付款人关系只按明确选择的单个实际付款人租客保存。
- [x] 月份已入账证据与同付款人历史流水仍可用，长内容和窄屏不遮挡关键操作。

## Out of scope

- 改动自动匹配规则、银行原始记录或已有分配的逐条编辑。已有错误分配继续走撤销后重做。
- 押金与其他收入归类；流水详情页原有「归类／拆分」继续承担这些用途。
- 数据库迁移。
