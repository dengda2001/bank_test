# 统一自动生成与入住分担领域

## Goal

让系统从房间入住安排自动形成稳定的月度应收与个人责任；房东通过租客资料及入住配置表达成员和分担，不维护账单或租约技术实体。

## Requirements

- 结构化房间的租金安排是月度应收来源；`tenants.monthly_rent_cents` 只用于未绑定房间的 legacy 兼容租客。
- 同一房间同一月份最多存在一条有效房间总应收；同一应收下每位租客最多一条个人责任。重复访问、重复生成和并发请求均保持幂等。
- 同一入口负责确保工作台、租客历史、流水匹配、现金收款和催收需要的月度责任事实完整。
- 普通浏览未来月份只展示预测。月份开始时可固化该月安排；明确将付款分配至未来月份时，也可固化对应安排。已固化责任不因之后的入住或租金调整而静默重算。
- 租住配置按整月生效；租客同一月份最多属于一个房间。多人责任默认均分，余数按稳定规则分配；可指定不等金额，但责任总和必须精确等于房间月租。
- 加入、移出、换房、退租、租金或分担变更，在一个事务中版本化房间安排和所有成员责任；房间存在当前或未来已固化账务事实时，不得覆盖这些月份。
- 结构化租客不得同时进入 legacy lazy generator。发现相同租客月份已存在互相冲突的 legacy 与结构化事实时，阻断自动双生成并返回可识别错误，不删除或改写已有付款／现金／催收历史。
- 所有查询与写入按当前 `user_id` 限定；不根据旧文本房间地址推断结构化关系。

## Acceptance Criteria

- [ ] 结构化单人租客承担房间全额；多人默认均分且余数规则稳定；不等分金额守恒，不守恒时事务回滚。
- [ ] 空房间不产生个人责任；未绑定租客不产生结构化责任。
- [ ] 同一房间同月只生成一条房间总应收及一组个人责任；重复和并发确保不会重复记账。
- [ ] 工作台、租客历史、匹配、现金与催收共用相同持久化个人责任 ID。
- [ ] 普通读取未来月份不会创建应收；月份开始或明确分配未来预付款可以固化，后续安排变更不重算已固化金额与责任人。
- [ ] 结构化租客不会被 legacy lazy generator 再生成个人责任；冲突数据被显式阻断并保留历史关系。
- [ ] 入住、离开、换房、改租金／分担在单事务内完成；已固化月份锁定，历史账务和分配保持不变。
- [ ] 租客、房间、安排及账务关系读写均通过当前用户作用域。

## Dependencies

- 本子任务为总任务 `.trellis/tasks/09-21-simplify-billing-tenancy` 的第一实施块。
- UI／导航子任务 `.trellis/tasks/09-21-simplify-rent-ui-routes` 必须等待本任务完成并通过其账务生成与入住分担验收；依赖关系以该子任务 PRD 与实施清单为准。

## Out of Scope

- 删除租约／账务表或批量迁移旧文本租客关系。
- 修改用户可见导航、页面模板或 `/bills` 路由。
- 月中按日折算、押金、杂费、多币种换汇和一个租客同月多房间。
