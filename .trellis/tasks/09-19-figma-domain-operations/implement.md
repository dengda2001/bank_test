# 领域写入实施计划

## 顺序

1. 开发前读取本包 Trellis 规范，盘点现有迁移、表索引、租金账本和 MySQL 测试夹具。
2. 增加可回滚的 schema：发票 URL、人工平账原因，以及必要的查询索引；先为迁移写升级测试。
3. 实现资产创建／编辑／停用服务和有效安排服务，所有新输入以 ID 和未来月份为准。
4. 改造新租客入住、退租／换房和房间价格／成员变更的服务入口；保留未绑定租客。
5. 给人工平账和支出关联补输入验证、审计字段与事务测试。
6. 完成 Go 单测和可用的 MySQL 集成测试，再交付页面数据任务。

## 交接契约

交接给 `figma-page-data-routes`：稳定的资产／安排查询 API、人工平账的原因参数、支出 URL 字段及错误类型。该任务不得自行重新实现守恒、有效期或停用校验。

## 验证

```sh
go test ./cmd/truelayer-demo/...
go test ./...
```

在受控数据库上另行运行新增的关系、并发和迁移测试；不清理或修改用户数据。
