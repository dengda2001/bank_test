# 页面数据与路由设计

## 路由策略

`/bills` 是租金责任页，`/transactions` 是银行／手工交易处理页；保留旧 `/billing` 指向交易语义，避免破坏书签和现有 POST action。资产、租住安排和银行采用新规范 GET 路由，低层 OAuth、refresh、现金预览和催收 POST 路由继续存在。

## 读取模型

每页的 handler 先解析 URL 过滤器、从会话取得 user ID、调用领域服务，再生成预格式化的展示字段和精确动作 URL。共享 view model 包含月度范围、对象摘要、金额／状态、可执行动作、同步健康度和错误提示；模板不得重新聚合数据库行。

详情以实体 ID 加 user scope 查询，桌面抽屉与手机详情页使用同一条数据。未绑定租客与旧无关联支出明确标为未归属，而不是伪造房间关系。

## 操作流程

平账、催收、现金、交易撤销通过可渲染的预览／确认状态传递必要事实和错误；提交仍由现有或新增服务执行最终锁定和权限验证。银行按钮仅执行已存 refresh token 的刷新；没有授权或失败时返回可操作的重新授权状态。

## 交接

桌面／移动任务获得模板数据、数据属性和 action contract；它们可以调整 DOM 层级与断点，但不可在模板中查询数据库或绕过确认路径。
