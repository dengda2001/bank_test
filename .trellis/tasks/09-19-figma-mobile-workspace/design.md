# 移动工作台设计

## 信息架构

底部导航保留五个日常入口，低频管理项放入更多。首页不复用桌面层级表：以两列指标、人工待办和可展开对象卡提供“看一眼→点一下”的路径。列表卡首屏固定身份、金额、状态和主操作，复杂明细进入详情或展开区。

## 交互层级

手机详情页承担桌面右侧抽屉的信息量；编辑／确认承担短时任务的 sheet。sheet 使用遮罩、焦点控制、可关闭手势／按钮和粘性安全区确认栏。催收、平账、撤销等高风险动作必须把影响和确认放在同一 sheet 中。

## 视觉／断点

沿用桌面 token 但以移动原型的 13px 卡片圆角、44px 控件、紧凑标题和安全区为优先。360px 下多列动作和指标可退成单列；600px 以下内容最大宽度 560px 且底栏与 sheet 同宽居中。移动 CSS 必须限定在移动断点，不能污染桌面表格。

## 与现有移动任务的衔接

先审计 `09-16` 已有卡片、fixture 和响应式规则：可复用的保留为共享基元，和 Figma 信息架构冲突的规则在合并说明后替换。不得同时存在两条不同的 `/billing` 或 `/rent-dashboard` 手机主路径。
