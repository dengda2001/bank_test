# 精简导航表单与兼容路由

## Goal

依赖统一账务生成和入住分担服务完成后，精简房东界面、导航和旧 bills/tenancies 路由。

## Requirements

- 桌面侧栏和手机底栏不再提供独立“应收账单”入口；月度应收、已收、未收和责任操作归入月度工作台租客视角。
- 房间表单是房间总月租、缴租日与生效月份的唯一维护入口。租客资料页可配置入住关系与个人分担；不要求房东单独维护租约或手工生成账单。
- 房间／租客详情以房东语言展示当前及历史入住和个人责任，不要求用户理解 agreement、charge、obligation 等内部对象。
- GET `/bills` 按月份与筛选上下文兼容跳转到 `/rent-dashboard?view=tenants&period=...`。`/billing` 是旧银行流水匹配别名，保持其现有行为。
- `/bills/settle`、`/tenancies` 和已有 POST／详情链接保留兼容行为或安全别名；工作台操作返回原月份与视角，旧深链不得 404。
- 交易匹配、现金、人工平账、催收及租客历史继续引用稳定的个人责任 ID 和现有审计关系。

## Acceptance Criteria

- [ ] 桌面和移动主导航均无独立账单入口，工作台租客视角可查看和操作应收责任。
- [ ] 新建房间只需设置房间总租金、缴租日与生效月份；租客可不绑定房间创建。
- [ ] 绑定租客时能看到房间总租金、全部入住人、默认均分、可编辑责任金额和金额守恒反馈。
- [ ] 房东不需要单独创建／编辑租约或点击生成账单；空房间和未绑定租客状态明确。
- [ ] `/bills` 迁移筛选月份到工作台租客视角；`/billing` 银行流水别名不变。
- [ ] `/bills/settle`、`/tenancies` 及工作台相关动作保留兼容和正确返回上下文。
- [ ] 页面操作不丢失付款分配、现金和催收审计事实；桌面与窄屏渲染可用。

## Dependencies

- 必须等待 `.trellis/tasks/09-21-rent-domain-auto-facts` 完成并验收。先建立唯一的自动生成及入住责任服务，再把界面接到该服务，避免新 UI 暴露仍有重复生成风险的调用链。
- 总任务 `.trellis/tasks/09-21-simplify-billing-tenancy` 在本子任务与领域子任务完成后负责集成验收。

## Out of Scope

- 删除 `/billing` 银行流水兼容别名或删除底层账务／租约模型。
- 旧租客文本房间关系的自动推断和批量迁移。
