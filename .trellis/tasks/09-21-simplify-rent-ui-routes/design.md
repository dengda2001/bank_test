# 设计：精简收租页面与兼容路由

## 页面与导航

隐藏独立应收账单产品入口，将它已有的月度责任读取与操作放在月度工作台租客视角。页面继续消费 `rent_obligations` 持久化责任事实。房间页维护总租金规则，租客表单维护人员资料和可选入住配置；展示默认均分及明确金额，并由后端领域服务校验守恒。租约页面不再作为可写房东模块；历史记录如继续展示则只读。

桌面和移动导航共享同一产品信息架构；工作台操作和返回链接带上 `period`、`view` 及安全的站内 `return_to` 上下文。模板不自行从显示字符串重建账务金额。

## URL 兼容

- `/bills` GET：读取允许迁移的 `period`／筛选参数，跳转至 `/rent-dashboard?view=tenants&period=...`。
- `/bills/settle` 和已有写操作：保留原 handler 或安全映射至规范工作台动作；拒绝外站 `return_to`。
- `/tenancies`：保留兼容重定向或只读历史呈现，旧详情与编辑深链不得 404 或执行无提示的破坏性写入。
- `/billing`：保留银行流水匹配别名，不能和 `/bills` 一起移除。

## 操作数据流

工作台／租客表单 → 现有认证 session `userID` → 领域服务验证并版本化安排／确保月度责任 → server-rendered view model → 共享桌面及移动模板。现金、催收、匹配继续使用责任 ID，旧入口重定向不能创建平行责任。

## 回滚

导航和页面改动可回退至现有页面，同时保留领域层统一生成服务。兼容路由在本任务内始终保留，不要求数据库 migration。
