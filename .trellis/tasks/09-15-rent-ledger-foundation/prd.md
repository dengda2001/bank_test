# 收租账本基础与账单生命周期

## 目标

建立所有收租页面共享的、可审计且可并发校验的账本基础。银行收款、现金补录、账单历史、Dashboard 和催缴必须从同一份有效收款事实读取，不以页面状态或可变的原始银行流水重复计算。

## 范围

- 为现有租金账单和收款分配设计向后兼容的数据迁移：区分有效／作废账单、有效／已撤销收款，保留确认人、时间、来源、请求幂等键与更正原因。
- 支持一笔来源收款拥有多项有效分配；每项用途是房租、押金或其他收入。账单实收只累计有效房租项；押金和其他收入有独立有效金额查询口径。
- 原始银行流水与账本分配分离：原始金额、日期、付款人、描述和参考号不可因归类、更正或重试被改写。
- 实现共享不变量：同一来源收款的累计有效分配不超原金额；租金项不超账单未收且币种一致；各项归属于同一用户；账单余额不为负。
- 定义可复用账单状态读取：未缴、部分缴纳、已缴清是互斥金额状态；逾期是附加状态。日期计算使用 `Europe/Dublin`，应缴日次日起逾期。
- 支持账单作废的存储与读取语义：作废账单保留审计记录，不进入应收、实收、未收、人数或催缴候选；不能通过隐式删除抹掉历史。
- 一期所有账单和收款只接受 EUR；保留三位币种字段和比较边界，为未来多币种扩展留口子，但不做换汇或跨币种相加。所有写入在事务中重检余额和来源可用金额；重复提交／重试不重复记账，竞争写入不能超分配。

## 不在本任务中

- 租客字段、付款人关系、租期编辑和历史页面（子任务 2）。
- 银行拉取、用途 UI、匹配、拆分、撤销工作流（子任务 3）。
- 现金录入（子任务 4）、Dashboard（子任务 5）和邮件（子任务 6）。
- 租金版本、预存款、退款、跨租客拆分。

## 验收标准

- [ ] 迁移后已有已确认银行收款继续准确计入原账单；未确认流水不被误计，原始流水不被改写。
- [ ] 同一来源的有效房租、押金、其他收入与未分配余额满足金额守恒；任何一项撤销后只撤回自身有效贡献，重复撤销无影响。
- [ ] 租金项在事务提交时同时校验来源余额、账单余额、EUR 币种和用户归属；非 EUR 输入被明确拒绝或保持待处理，两个并发请求不能使任一限制被突破。
- [ ] Dublin 应缴日当天不显示逾期，次日起显示逾期天数；结清后逾期消失，作废账单不进入有效统计。
- [ ] 账本读取接口能按账单月、银行到账月、用途、来源和币种提供后续页面需要的一致结果；一期展示仅返回 EUR，不依赖 UI 层重复汇总，并保留未来扩展的币种边界。

## 依赖与风险

无上游功能依赖；它是后续全部子任务的必经基础。设计必须先处理现有 `payment_allocations` 的 `(transaction, obligation)` 唯一约束、`rent_obligations.paid_amount_cents` 的兼容策略以及可逆审计迁移。
