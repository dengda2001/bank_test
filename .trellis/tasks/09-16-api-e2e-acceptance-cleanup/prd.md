# 真实 API 全链路验收与测试数据清理

## 目标

在全部收租后端逻辑交付后，以新建、完全隔离的测试账户和一组真实结构的银行流水样例，针对运行中的应用逐一调用业务 HTTP 接口，完成可重复的端到端验收。每一个响应、金额、币种、账单状态、流水余款、汇总数和审计结果必须与测试数据的预期精确相符；全部通过后安全删除本次运行创建的全部测试数据，不留下残留。

## 前置条件

本任务是父任务 `09-15-landlord-rent-operations` 的第七个子任务，且必须在下列六项均已完成、验证并归档后才可启动：

1. `09-15-rent-ledger-foundation`
2. `09-15-tenant-profile-and-history`
3. `09-15-bank-receipt-management`
4. `09-15-cash-rent-receipts`
5. `09-15-monthly-rent-dashboard`
6. `09-15-monthly-rent-dunning`

最终 UI 子任务 `09-16-ui-consistency-flat-design` 必须等待本任务全量通过和测试数据清理验证后才能启动。

## 范围与约束

- 在实现前，从最终路由与接口契约生成业务 HTTP 接口清单；认证、租客、付款人、账单／历史、银行流水、分类与拆分、续配／撤销、现金、Dashboard、催缴及其查询、筛选、分页和错误路径均须覆盖。每一项接口必须有成功断言和适用的非法输入、越权、幂等／重复提交或状态冲突断言，不能只测页面能打开或 HTTP 200。
- 新建一个本次运行专属的测试账户。账户、邮箱／用户名、租客、付款人、账单、银行流水稳定键／流水号、描述、现金记录、催缴记录及其他测试实体均使用唯一的运行标识前缀，形成可审计的测试数据清单。
- 先准备一批具有真实字段结构和确定金额的原始银行流水样例，包括完整收租、部分收租、跨月拆分、房租／押金／其他收入混合用途、未分配余额、错误归属后整体撤销并重新匹配、无需匹配、非 EUR 拒绝或待处理，以及自动匹配证据不足的场景。每条流水号／稳定键必须唯一且可由测试预期精确追溯。
- 除了受控地准备测试账户和原始银行流水等基础事实以外，租客、付款人关系、账单操作、分类、绑定／拆分、续配、撤销、现金补录／作废、查询、Dashboard 和催缴等业务状态都必须通过实际 HTTP 接口创建、读取和变更；不得通过直接改库绕过待验收的业务逻辑。
- 测试应从账户认证开始，以同一会话／令牌真实调用接口，并将已知输入与每次响应保存为机器可读的预期／实际结果。金额一律以系统规定的精确货币表示比较，不以浮点近似或页面肉眼判断代替断言。
- 对所有写操作在随后的读取接口、历史接口和汇总接口中交叉验证。特别验证：金额守恒、EUR-only、租金所属月份与到账月份分离、Dublin 日期口径、状态转换、撤销只撤回自身贡献、重复请求不重复入账，以及用户隔离不能被猜测 ID 绕过。
- 执行环境必须是可安全清理的隔离环境或数据库。不得对真实用户、真实银行连接或无明确运行标识的数据写入、修改或删除；清理逻辑只能按本次测试账户和运行前缀的明确 allowlist 执行，并在目标不匹配时失败停止。
- 全部断言成功后，删除本次运行创建的基础数据、业务数据和测试账户（如账户由本次任务创建）；随后以接口和受控查询双重确认零残留。若任一断言失败，不得把失败伪装为通过；保留失败报告与运行标识以便诊断，并只能按相同的隔离规则显式清理。

## 验收标准

- [ ] 所有六个前置子任务已完成并归档，且存在最终业务 HTTP 接口清单；清单中的每个接口和每个有意义的结果状态均有可重复的端到端场景与精确断言。
- [ ] 已通过应用支持的认证／账户入口创建唯一测试账户，并生成带同一运行标识的测试数据清单；没有使用真实客户或真实银行数据。
- [ ] 已准备多笔唯一流水号／稳定键的真实结构样例，并通过接口创建租客、付款人关系及其余业务状态；测试脚本没有用直接数据库写入替代任何待测业务接口。
- [ ] 所有创建、绑定、分类、拆分、续配、撤销、现金更正、查询、汇总、催缴及相关错误／越权／重复请求场景的响应和后续读取结果，都与预期状态及精确数值相同。
- [ ] 每个场景的金额守恒成立：`原流水金额 = 有效房租 + 有效押金 + 有效其他收入 + 未分配余额`；跨月分配、部分收款、撤销重配和现金来源均不会造成重复、丢失或跨用户记账。
- [ ] 已验证 Dashboard、账单历史和催缴读取到同一账本事实；筛选、分页和账户隔离不改变金额口径，也不会泄露或改变另一账户的数据。
- [ ] 自动化运行产出可审计的通过／失败报告，包含运行标识、接口／场景、预期与实际值；任何未通过的断言都使任务失败。
- [ ] 在所有测试通过后，仅删除本次运行标识和测试账户范围内的数据；清理后接口查询和受控数据检查均确认测试账户、流水号、租客、付款人、账单、分配、现金及催缴记录零残留，且未影响任何非测试数据。

## 非范围

- 不以此任务替代各子任务已有的单元、集成、迁移和并发测试；它们仍是本端到端验收的前置质量门槛。
- 不测试需要真实房东授权或真实银行数据的第三方生产 OAuth／银行同步；这类外部依赖只能使用安全的 sandbox、stub 或已经隔离的测试凭据。
- 不进行页面视觉、组件一致性或手机端布局验收；这些工作由后续 `09-16-ui-consistency-flat-design` 任务承担。

## 执行前待落实的安全决策

- 启动前必须确认一个允许创建和删除隔离账户／数据的非生产目标环境，以及该环境的认证方式和受控数据查询方式。若没有这样的环境或用户的明确隔离授权，本任务不得执行任何创建或删除操作。

## 规划核对

### 已确认

- 应用当前通过 `/login-local` 使用账号密码登录，数据库连接由 `MYSQL_DSN`
  或 `DATABASE_URL` 提供；没有现成的 E2E runner 或按运行标识清理脚本。
- 本任务可以复用现有真实 HTTP 路由和 MySQL 迁移，但必须先获得一个可丢弃的
  非生产数据库；本地单元／MySQL 集成测试在没有 `RENTOPS_MYSQL_TEST_DSN` 时会跳过。
- legacy 原始流水输入需要由 `RENTOPS_E2E_FIXTURE_DIR` 指向的专用空目录承载；runner
  不覆盖已有目录内容，应用启动时应将 `TL_LOG_FILE`、`TL_TENANT_FILE` 和
  `TL_EXPENSE_FILE` 配置到本目录内的三个文件。
- 代码仓库和历史会话没有提供可直接使用的隔离测试账户、测试数据库连接、认证凭据
  或受控数据查询入口。

### 待用户确认（当前阻塞）

- 需要一个允许本轮创建并在断言成功后删除测试账户／业务数据的非生产目标环境、认证方式
  和受控查询方式；未确认前不创建账户、不写入数据、不执行清理。
- 还需要一个预先播种在同一隔离库中的第二测试账户（用于跨用户 ID 拒绝断言）以及
  明确指向本轮的 SMTP sink；二者缺失时 runner 预检失败。
