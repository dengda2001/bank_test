3. **历史查询服务**

   - 为跨用户租客／账单／分配、日期边界、分页和多笔收款增加服务与投影测试。

4. **HTTP 路由与模板**
   - 注册 `GET /tenants/{id}`、付款人关系 POST 操作，并复用现有认证和账户 ID 获取逻辑。

   - 保证页面不会展示其他用户资源存在性，所有提交后 redirect 只携带非敏感状态码。

5. **兼容性整理**
   - 更新 legacy import 和当前列表的 view model；确认旧 JSON 数据仍能打开，数据库模式下不回退到全局文件。
   - 检查现有匹配、Dashboard 和历史模板仍通过既有账本投影读取，不因新增付款人表重复计收。

## 必须覆盖的验收场景

- 新建租客不填计费开始日时默认租期开始日；延后日期超出租期或邮箱格式错误时显示字段级错误；重新编辑不会覆盖已有日期。
- 一个租客可有多个付款人关系；至少覆盖只有名称、没有稳定 ID 的现有流水形态；同名关系出现在多个租客时标记共享／冲突候选；移除后旧收款和历史仍原样存在。
- 详情选择超过三个月期间时，每个适用月最多一个账单；无收款月可见，同月多笔有效收款汇总并可展开。
- 修改月租不改写已生成账单；历史补建月明确显示“历史租金待核对”。
- 提前退租对无收款未来账单全部作废；任何受影响账单已有有效银行或现金收款时，保存失败且不部分作废；停用不隐藏旧欠款。
- 所有详情、付款人增删、账单和历史查询按当前用户隔离；非 EUR 租客输入被拒绝。

## 风险点与回滚点

- **迁移回滚点**：应用新代码前确认 `004` 在测试数据库可重复执行；失败只允许通过迁移事务回滚，不手工删除生产表。
- **生命周期回滚点**：任何账单作废必须和租客更新在同一事务；发现有效分配后立即回滚整个事务。
- **路由回滚点**：若详情页模板失败，保留 `/tenants` 列表和原有折叠历史可用，不改变账本数据。
- **数据核对**：实施后检查旧租客数量、每月账单数量、有效分配金额和付款人关系回填数量，确保没有静默变更。
