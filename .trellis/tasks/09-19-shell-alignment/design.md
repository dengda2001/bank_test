# 技术设计：全局外壳对齐

父任务 `design.md` 的架构与边界同样适用，此处只记录本子任务独有的决策。

## 1. 边界

改：`web/templates/partials/workspace-nav.html`、`web/static/css/workspace.css`（外壳相关区块）。

不改：任何页面的主体内容结构、路由、视图模型契约。

外壳是全部 11 个页面的公共渲染点。**改错一处会同时打挂所有页面**，因此每次改动后必须全页面截图，不能只查目标页。

## 2. 关键决策

### 2.1 toast 的渲染位置与服务端契约

父任务 `design.md` §2.4 已定：toast 容器挂在共享外壳内，notice 数据仍由服务端在重定向后传入，**不改成 AJAX**。

落地要点：

- 容器放在 `workspace-nav.html` 内，所有页面自动具备。
- 服务端 notice 存在时渲染为 toast 并带 `data-autoshow`，共享内联 script 读到后触发显示与 2.2 秒消失。
- **同一消息不得出现两次**：现有 notice 块保留为无脚本降级，但默认样式下不可见。若直接保留可见就会与 toast 重复。
- 测试断言必须锚定声明而非注释 —— `responsive-conventions.md:170` 记录 `html/template` 会剥离 `<style>` 里的 CSS 注释。

### 2.2 顶部搜索框的作用域

父任务 A1 的硬约束：**不得做成无行为的假控件**。本次它承担当前页面的列表检索。

- 有 `search` 参数的页面：渲染搜索框，提交到该页已有参数。
- 无该参数的页面：**不渲染**，而不是渲染一个无效输入框。

跨实体全局检索已拆为后续任务，本子任务不实现。

### 2.3 导航计数不得改变渲染条件

`TestNavCountsOnlyRenderWhereTheyDidBefore` 断言现有 4 个计数只在既有位置渲染。补 `01`–`11` 数字图标、分组标题、状态卡时，**计数条件（`{{if .ShowNavCounts}}`）必须原样保留**。

这是本子任务最容易踩的坑：重排侧边栏结构时顺手把计数挪位置或改条件，测试会失败，且失败原因是"顺手改的"而非设计意图。

### 2.4 底部状态卡的数据来源

原型显示「测试数据已载入 / Rosewood 收租明细 / 更新于 2026-09-16」，这是演示态文案。

`figma/DESIGN-HANDOFF.md:37` 要求"保留导出中的真实文案"，`:9` 要求不得保留原型专属装饰。两者的分界是：**原型文案描述的是演示数据，不是产品信息**。因此状态卡应渲染真实数据源与真实更新时间；无真实来源的行不渲染，也不写死原型文案。

## 3. 兼容与回滚

外壳改动影响面最大，独立提交、可单独 revert。改后必须跑 `TestEveryWorkspacePageRendersTheSharedChromeOnce` 与全页面截图。

## 4. 验收方式

- 11 个页面逐页截图，四档宽度。
- 断言 `scrollWidth === clientWidth`。
- 用归档 harness 的 `verify-hits.mjs` 类脚本核验可点击区域（顶栏控件尺寸）；**只读**，见父任务 `implement.md` 的安全边界。
